\section{Purpose}

This guide explains how to use HydrologicalTwinAlphaSeries (HTAS) through its
public interface. HTAS reads the outputs of a CaWaQS simulation and computes on
them: water budgets, hydrological regimes, spatial maps, simulation against
observations with statistical criteria, and selections of a domain by a
polygon. It can be driven at three levels:

\begin{itemize}
    \item \textbf{the command line}, \texttt{htas} (Section~\ref{sec:cli});
    \item \textbf{the client}, \texttt{HydrologicalTwinClient}: one method per
    CaWaQS-ViZ operation (Section~\ref{sec:client});
    \item \textbf{the façade}, \texttt{HydrologicalTwin}: nine macro-verbs, each
    choosing its work by a \texttt{kind} (Section~\ref{sec:facade}).
\end{itemize}

Do not drive HTAS through \texttt{domain/}, \texttt{services/},
\texttt{tools/}, or private helper methods.

\section{Installation}

HTAS runs through Pixi:

\begin{verbatim}
pixi install
pixi run htas --version
\end{verbatim}

Run Python examples with \texttt{pixi run python}, or from a Pixi shell.

\section{The command line}\label{sec:cli}

\begin{verbatim}
pixi run htas detect run /data/OUT_CAW --write htas.toml
pixi run htas detect neighbors /data/project.qgz --write htas.toml
pixi run htas describe --project htas.toml --layer AQ_LAYER=/data/gis/aq.gpkg
\end{verbatim}

\begin{center}
\begin{tabularx}{\textwidth}{l l X}
\toprule
\textbf{Command} & \textbf{Calls} & \textbf{Does} \\
\midrule
\texttt{htas detect run} & \texttt{detect\_from\_out\_caw} & Detects a CaWaQS output directory's settings \\
\texttt{htas detect neighbors} & \texttt{detect\_project\_neighbors} & Detects the files around a QGIS project \\
\texttt{htas describe} & \texttt{describe} & Builds the twin and lists its compartments \\
\texttt{htas budget barplot} & \texttt{budget\_barplot} & Budget bar plot and CSV \\
\texttt{htas regime show} & \texttt{hydrological\_regime} & Hydrological regime plot \\
\texttt{htas map watbal} & \texttt{spatial\_map\_watbal} & Water-balance map \\
\texttt{htas map aq} & \texttt{spatial\_map\_aq} & Aquifer map \\
\texttt{htas compare simobs} & \texttt{compare\_sim\_obs} & Simulation against observations \\
\texttt{htas criteria compute} & \texttt{statistical\_criteria} & Statistical criteria at observation points \\
\texttt{htas mask internal} & \texttt{mask\_internal\_values} & Values of the cells inside a polygon \\
\texttt{htas mask hyd} & \texttt{mask\_hyd\_boundary} & River reaches on a polygon's boundary \\
\texttt{htas mask aq} & \texttt{mask\_aq\_boundary} & Aquifer faces on a polygon's boundary \\
\bottomrule
\end{tabularx}
\end{center}

\begin{verbatim}
pixi run htas budget barplot --period 2000-01-01 2010-12-31 \
    --frequency Y --agg sum --output-dir /data/out
pixi run htas mask internal --polygon /data/area.gpkg \
    --spec AQ:MB:recharge:m3/j --output-dir /data/out \
    --temp-dir /data/tmp --area-name basin
\end{verbatim}

\begin{itemize}
    \item \texttt{--write FILE} saves what \texttt{detect} found into a project file, \texttt{htas.toml} by convention.
    \item The twin is read from the project file (\texttt{--project}, or \texttt{htas.toml} in the current directory). The options \texttt{--out-caw}, \texttt{--obs-dir}, \texttt{--geometry-config}, \texttt{--years START END} and \texttt{--layer NAME=PATH} (repeatable) override it.
    \item An operation command takes the options of its client method, named after its keyword (\texttt{output\_dir} is \texttt{--output-dir}); the method's required arguments are required, and an option left out is not passed. \texttt{htas <command> <subcommand> --help} lists them. A period is two dates (\texttt{--period START END}); \texttt{--agg} is \texttt{sum}, \texttt{mean}, \texttt{max}, \texttt{min} or a quantile.
    \item \texttt{htas mask} reads its polygon from a vector file (\texttt{--polygon FILE}, all its features merged; \texttt{--polygon-crs} if the file has no CRS) and the simulated years from the project file or \texttt{--years}. \texttt{htas mask internal} takes \texttt{--spec COMPARTMENT:OUTTYPE:PARAM:UNIT} (repeatable) or \texttt{--specs-file}, a JSON list; \texttt{htas map aq} takes \texttt{--mode KEY=VALUE} (repeatable) or \texttt{--mode-file}, a JSON object.
    \item \texttt{--json} prints the result as JSON.
    \item Exit codes: \texttt{0} done; \texttt{1} it ran and the answer is no (a twin in the wrong state); \texttt{2} it could not run (bad arguments, a missing or unreadable file, a directory that is not a CaWaQS run).
    \item \texttt{htas --help} lists the commands, \texttt{htas <command> --help} gives each subcommand with an example, and a mistyped command gets a suggestion.
\end{itemize}

\section{The client}\label{sec:client}

\subsection{Building a client}

\begin{verbatim}
from HydrologicalTwinAlphaSeries.config import ConfigGeometry, ConfigProject
from HydrologicalTwinAlphaSeries.ht.client import HydrologicalTwinClient
from HydrologicalTwinAlphaSeries.services.public import FileGeoProvider

config_geom = ConfigGeometry.fromJsonFile("/data/geometry.json")
config_proj = ConfigProject.fromDict(
    {
        "json_path_geometries": "/data/geometry.json",
        "projectName": "demo",
        "cawOutDirectory": "/data/OUT_CAW",
        "startSim": 2000,
        "endSim": 2010,
        "obsDirectory": "/data/OBS",
        "regime": "Transient",
    }
)

client = HydrologicalTwinClient.build(
    {"project_name": "demo", "start_year": 2000, "end_year": 2010},
    configure_kwargs={
        "config_geom": config_geom,
        "config_proj": config_proj,
        "out_caw_directory": "/data/OUT_CAW",
        "obs_directory": "/data/OBS",
    },
    load_kwargs={"geo_provider": FileGeoProvider({"AQ_LAYER": "/data/gis/aq.gpkg"})},
)
\end{verbatim}

The client operations read the simulated period from the metadata: its
\texttt{start\_year} and \texttt{end\_year} keys are required.
\texttt{HydrologicalTwinClient.detect\_from\_out\_caw} and
\texttt{detect\_project\_neighbors} return the settings they find, to fill
these dictionaries. \texttt{is\_ready()} says whether the twin is loaded.

\subsection{The operations}

Each operation runs a whole fetch--transform--render chain and returns a typed
result. Its keyword arguments are those of
\texttt{operations\_client.run\_<name>}: the table lists the required ones,
then, in brackets, the optional ones.

\midrule

\texttt{hydrological\_regime} & \texttt{compartment\_name}, \texttt{outtype}, \texttt{param}, \texttt{var\_label}, \texttt{units}, \texttt{savepath} [\texttt{interactive}, \texttt{staticpng}, \texttt{staticpdf}, \texttt{period}] & \texttt{HydrologicalRegimeResult} \\

\section{The façade}\label{sec:facade}

\subsection{Public imports}

\begin{verbatim}
from HydrologicalTwinAlphaSeries import (
    ConfigGeometry,
    ConfigProject,
    HydrologicalTwin,
)
from HydrologicalTwinAlphaSeries.ht import (
    ConfigureRequest,
    DescribeRequest,
    ExportRequest,
    FetchRequest,
    LoadRequest,
    MaskRequest,
    RenderRequest,
    TransformRequest,
)
\end{verbatim}

\subsection{The nine macro-verbs and the lifecycle}

\begin{center}
\texttt{EMPTY} $\rightarrow$ \texttt{CONFIGURED} $\rightarrow$ \texttt{LOADED} $\rightarrow$ \texttt{READY}
\end{center}

\begin{itemize}
    \item \texttt{configure} moves the twin from \texttt{EMPTY} to \texttt{CONFIGURED}.
    \item \texttt{load} moves it from \texttt{CONFIGURED} to \texttt{LOADED}.
    \item \texttt{describe}, \texttt{fetch}, \texttt{mask}, \texttt{transform},
    \texttt{assemble}, \texttt{render} and \texttt{export} require \texttt{LOADED}.
    \item \texttt{READY} is reserved for consistency checks to come; no verb reaches it yet.
\end{itemize}

A verb called too early raises \texttt{InvalidStateError}. Each verb takes a
request dataclass, or the same fields as keywords.

\subsection{Step 1 --- Configure}

You can configure the twin at construction time or call \texttt{configure()}.

\begin{verbatim}
twin = HydrologicalTwin(
    config_geom=config_geom,
    config_proj=config_proj,
    out_caw_directory="/data/OUT_CAW",
    obs_directory="/data/OBS",
    temp_directory="/data/TEMP",
    metadata={"consumer": "user-guide"},
)
\end{verbatim}

\begin{verbatim}
twin = HydrologicalTwin()
twin.configure(
    request=ConfigureRequest(
        config_geom=config_geom,
        config_proj=config_proj,
        out_caw_directory="/data/OUT_CAW",
        obs_directory="/data/OBS",
        temp_directory="/data/TEMP",
    )
)
\end{verbatim}

\subsection{Step 2 --- Load}

\texttt{load} builds the compartments from the layers a layer provider
serves, and writes the NumPy cache of the simulation outputs.

\begin{verbatim}
twin.load(
    request=LoadRequest(
        ids_compartments=[1, 2, 3],
        geo_provider=FileGeoProvider({"AQ_LAYER": "/data/gis/aq.gpkg"}),
    )
)
\end{verbatim}

Compartments are numbered as CaWaQS numbers them: \texttt{1} AQ, \texttt{2}
HYD, \texttt{3} WATBAL, \texttt{4} NSAT.

\subsection{Step 3 --- Describe}

\begin{verbatim}
description = twin.describe(request=DescribeRequest())

print(description.state)
print(description.n_compartments)
print(description.catalog.extract_kinds)
print(description.catalog.transform_kinds)
print(description.catalog.render_kinds)
print(description.catalog.export_formats)
\end{verbatim}

\subsection{Step 4 --- Fetch}

Kinds: \texttt{simulation\_matrix}, \texttt{observations},
\texttt{sim\_obs\_bundle}, \texttt{spatial\_map}, \texttt{catchment\_cells},
\texttt{aquifer\_outcropping\_map}, \texttt{aq\_balance\_inputs}.

\begin{verbatim}
values = twin.fetch(
    request=FetchRequest(
        kind="simulation_matrix",
        id_compartment=1,
        outtype="MB",
        param="recharge",
        syear=2000,
        eyear=2010,
    )
)
print(values.data.shape, values.dates[:3])

bundle = twin.fetch(
    request=FetchRequest(
        kind="sim_obs_bundle",
        id_compartment=2,
        outtype="Q",
        param="discharge",
        syear=2000,
        eyear=2010,
    )
)
\end{verbatim}

\subsection{Step 5 --- Mask}

Kinds: \texttt{polygon\_cells}, \texttt{area\_values}, \texttt{boundary\_hyd},
\texttt{boundary\_hyd\_flux}, \texttt{boundary\_aq}, \texttt{boundary\_aq\_flux}.

\begin{verbatim}
cells = twin.mask(
    request=MaskRequest(
        kind="polygon_cells",
        id_compartment=1,
        polygon=polygon,
        polygon_crs="EPSG:2154",
    )
)
print(cells.cell_ids[:10])
\end{verbatim}

\subsection{Step 6 --- Transform}

Kinds: \texttt{temporal\_aggregation}, \texttt{temporal\_aggregate},
\texttt{spatial\_average}, \texttt{volumetric\_rescale}, \texttt{criteria},
\texttt{budget}, \texttt{hydrological\_regime}, \texttt{runoff\_ratio},
\texttt{aq\_balance}.

\begin{verbatim}
monthly = twin.transform(
    request=TransformRequest(
        kind="temporal_aggregation",
        data=values.data,
        dates=values.dates,
        frequency="Monthly",
        agg_dimension="mean",
    )
)

criteria = twin.transform(
    request=TransformRequest(
        kind="criteria",
        bundle=bundle,
        metrics=["nash", "kge", "rmse", "pbias"],
    )
)

regime = twin.transform(
    request=TransformRequest(
        kind="hydrological_regime",
        id_compartment=2,
        outtype="Q",
        param="discharge",
        sdate=2000,
        edate=2010,
    )
)
\end{verbatim}

\subsection{Step 7 --- Render}

Kinds: \texttt{budget\_barplot}, \texttt{hydrological\_regime},
\texttt{sim\_obs\_pdf}, \texttt{sim\_obs\_interactive}, \texttt{aq\_flux\_diagram}.

\begin{verbatim}
regime_plot = twin.render(
    request=RenderRequest(
        kind="hydrological_regime",
        data=regime.data,
        obs_point_names=regime.obs_point_names,
        month_labels=regime.month_labels,
        var="discharge",
        units="m3/s",
        savepath="/data/out/regime",
        interactive=False,
        staticpng=True,
        staticpdf=True,
    )
)
print(regime_plot.artefacts)
\end{verbatim}

\subsection{Step 8 --- Assemble and export}

\texttt{assemble} shapes computed blocks into a payload ready to write
(\texttt{compartment\_bundle}, \texttt{boundary\_aq\_layers}); \texttt{export}
writes data files, by format (\texttt{npy}, \texttt{geopackage}). It never
computes and never draws.

\begin{verbatim}
written = twin.export(
    request=ExportRequest(
        kind="npy",
        path="/data/out/recharge.npy",
        data=values.data,
    )
)
print(written.path)
\end{verbatim}

GeoPackages are written by the client's mask operations with
\texttt{write\_geopackage=True}, which assemble and export for you.

\section{What not to do}

\begin{itemize}
    \item Do not import from \texttt{domain/}, \texttt{services/} or private helpers.
    \item Do not build or change \texttt{Compartment}, \texttt{Mesh}, \texttt{Observation} or \texttt{Extraction} objects yourself.
    \item Do not skip the lifecycle order.
    \item Do not rely on methods not listed in this guide, such as \texttt{read\_values()}.
\end{itemize}
