\section{Goal}

The \texttt{HydrologicalTwin} (HT) is a monolithic backend façade for CaWaQS-ViZ.  
It is designed as the \emph{only} backend entry point used by the QGIS plugin.

HT reuses the existing CaWaQS-ViZ code base without rewriting it, including:
\begin{itemize}
    \item \texttt{Compartment}, \texttt{Mesh}, \texttt{Observations}, \texttt{Extraction}
    \item \texttt{Manage.Temporal}, \texttt{Manage.Budget}, \texttt{Manage.Spatial}
\end{itemize}

It exposes a clean and stable API for:
\begin{itemize}
    \item value extraction from CaWaQS binary outputs,
    \item temporal aggregation,
    \item mass balance and budget analysis,
    \item spatial operators (catchment cells, aquifer outcropping).
\end{itemize}

It also supports persistence via \texttt{.pkl} files for bancarisation.

This architecture deliberately does not rewrite the existing code base; instead, it wraps it and formalizes a clear interface for all front-end clients.

\section{Integration with Existing CaWaQS-ViZ Code}

\subsection{Package Layout}

The new \texttt{ht} subpackage is introduced inside the existing \texttt{cawaqsviz} package:

\begin{verbatim}
cawaqsviz/
    Compartment.py
    Mesh.py
    Observations.py
    Extraction.py
    Manage.py
    interface/
        Config.py
    ht/
        __init__.py
        hydrological_twin.py
        api_types.py
        persistence.py
\end{verbatim}

The existing modules (\texttt{Compartment}, \texttt{Mesh}, \texttt{Observations}, \texttt{Extraction}, \texttt{Manage}) remain unchanged.

\subsection{HydrologicalTwin Construction}

The \texttt{HydrologicalTwin} is built from the same configuration objects already used by \texttt{Compartment}:
\begin{itemize}
    \item \texttt{ConfigGeometry}
    \item \texttt{ConfigProject} (e.g. regime)
    \item \texttt{out\_caw\_directory} (root of CaWaQS outputs)
    \item \texttt{obs\_directory} (root of observation data)
    \item \texttt{temp\_directory} (optional, defaults to CaWaQS outputs directory)
\end{itemize}

The constructor stores these references and instantiates the service layers:
\begin{itemize}
    \item \texttt{Manage.Temporal()}
    \item \texttt{Manage.Budget()}
    \item \texttt{Manage.Spatial()}
\end{itemize}

\section{Domain Model and Encapsulation}

\subsection{Compartments}

HT maintains an internal mapping:
\[
\texttt{self.compartments: Dict[int, Compartment]}
\]

\begin{itemize}
    \item \texttt{build\_compartment(id\_compartment)} calls the existing \texttt{Compartment} constructor.
    \item \texttt{get\_compartment(id\_compartment)} returns an existing instance or builds it on demand.
\end{itemize}

The GUI must never construct \texttt{Compartment} objects directly.  
All access goes through \texttt{HydrologicalTwin.get\_compartment()} or higher-level HT methods.

\subsection{Observations, Mesh, Extraction}

These classes remain internal implementation details of \texttt{Compartment}.  
They are not exposed to the GUI. All access goes through explicit methods on \texttt{HydrologicalTwin}.

\section{HydrologicalTwin Backend API}

The HT API consists of the public methods of the \texttt{HydrologicalTwin} class.  
Each method is a thin wrapper around existing domain logic.

\subsection{\texttt{extract\_values(...)}}

\textbf{Purpose:}  
Read CaWaQS binary outputs, build a time-series DataFrame, and optionally write a CSV.

\textbf{Implementation:}
\begin{itemize}
    \item Retrieve or build the compartment:
    \begin{verbatim}
comp = self.get_compartment(id_compartment)
    \end{verbatim}

    \item Call:
    \begin{verbatim}
temporal.readSimData(...)
    \end{verbatim}

    \item Convert to DataFrame:
    \begin{verbatim}
temporal.simMatrixToDf(...)
    \end{verbatim}

    \item Optionally write a tab-separated CSV.
\end{itemize}

The method returns an \texttt{ExtractValuesResponse} containing:
\begin{itemize}
    \item the DataFrame,
    \item the CSV path (if written),
    \item metadata.
\end{itemize}

\subsection{\texttt{apply\_temporal\_operator(...)}}

\textbf{Purpose:}  
Apply temporal aggregation (annual mean, monthly sum, quantiles, etc.).

It wraps:
\begin{verbatim}
Manage.Temporal.aggregate_matrix(...)
\end{verbatim}

The GUI provides the DataFrame to aggregate, typically produced by \texttt{extract\_values()}.

\subsection{\texttt{compute\_mass\_balance(...)}}

\textbf{Purpose:}  
Compute interannual budgets and mass balances.

Wraps:
\begin{verbatim}
Manage.Budget.calcInteranualBVariable(...)
\end{verbatim}

Returns a \texttt{MassBalanceResponse}.

\subsection{\texttt{apply\_spatial\_operator(...)}}

Provides a unified spatial API.

\begin{itemize}
    \item \texttt{operator = 'catchment\_cells'}  
    Wraps \texttt{Manage.Spatial.getCatchmentCellsIds(...)}  
    Returns a DataFrame with \texttt{id\_cell}.

    \item \texttt{operator = 'aquifer\_outcropping'}  
    Wraps \texttt{Manage.Spatial.buildAqOutcropping(...)}  
    Returns a DataFrame with \texttt{id\_abs}.
\end{itemize}

\subsection{\texttt{self\_fitting(...)}}

\textbf{Purpose:}  
Execute automated parameter calibration with full provenance tracking and private-key authentication.

\textbf{Access Control:}  
This method requires:
\begin{itemize}
    \item Successful twin instantiation with certified reproducibility
    \item Valid private-key authentication
    \item Access to registered observation datasets
\end{itemize}

\textbf{Method Signature:}

\begin{verbatim}
def self_fitting(
    self,
    target_observations: List[ObservationSet],
    parameters_to_calibrate: List[ParameterDescriptor],
    optimization_algorithm: str,
    convergence_criteria: Dict[str, float],
    private_key: str,
    **algorithm_kwargs
) -> CalibrationResult:
\end{verbatim}

\textbf{Parameters:}

\begin{itemize}
    \item \texttt{target\_observations}: List of observation sets with spatial locations, values, and uncertainties
    \item \texttt{parameters\_to\_calibrate}: Structured parameter specifications including priors and constraints
    \item \texttt{optimization\_algorithm}: Selection of optimization method (\texttt{'gradient\_descent'}, \texttt{'mcmc'}, \texttt{'bayesian\_inference'}, \texttt{'enkf'}, \texttt{'pso'}, \texttt{'multi\_stage\_bayesian'})
    \item \texttt{convergence\_criteria}: Dictionary with \texttt{max\_iterations}, \texttt{tolerance}, \texttt{objective\_function\_value}
    \item \texttt{private\_key}: Cryptographic key for authentication
    \item \texttt{algorithm\_kwargs}: Algorithm-specific parameters (learning rate, ensemble size, Bayesian inference chains, workflow stages, etc.)
\end{itemize}

\textbf{Return Value:}

Returns a \texttt{CalibrationResult} object containing:
\begin{itemize}
    \item \texttt{calibrated\_twin}: New \hydrot\ instance with optimized parameters
    \item \texttt{parameter\_evolution}: DataFrame tracking parameter values across iterations
    \item \texttt{objective\_function\_history}: Array of objective function values
    \item \texttt{convergence\_diagnostics}: Convergence test results and diagnostic plots
    \item \texttt{validation\_metrics}: Dictionary with RMSE, Nash-Sutcliffe efficiency, and other fit metrics
    \item \texttt{posterior\_distribution}: (Optional) Posterior samples for Bayesian methods
    \item \texttt{registry\_fingerprint}: Unique identifier for this calibration session
\end{itemize}

\textbf{Implementation Architecture:}

The method is implemented as a façade that coordinates multiple backend components:

\begin{enumerate}
    \item \textbf{Authentication layer}:
    \begin{verbatim}
auth_manager.validate_key(private_key)
auth_manager.log_calibration_event(user_id, timestamp)
    \end{verbatim}

    \item \textbf{Observation extraction}:
    \begin{verbatim}
obs_layer = self.estimation_layer.get_observations()
target_values = obs_layer.extract_at_locations(
    target_observations
)
    \end{verbatim}

    \item \textbf{Optimization loop}:
    \begin{verbatim}
optimizer = OptimizationFactory.create(
    algorithm=optimization_algorithm,
    **algorithm_kwargs
)
while not optimizer.has_converged(convergence_criteria):
    params = optimizer.propose_parameters()
    sim_twin = self.create_variant(params)
    sim_values = sim_twin.extract_at_locations(
        target_observations
    )
    objective = compute_mismatch(sim_values, target_values)
    optimizer.update(objective)
    registry.append(sim_twin, objective, timestamp)
    \end{verbatim}

    \item \textbf{Result instantiation}:
    \begin{verbatim}
optimal_params = optimizer.get_best_parameters()
calibrated_twin = HydrologicalTwin(
    config=self.config.with_parameters(optimal_params),
    private_key=private_key,
    parent_fingerprint=self.registry_fingerprint
)
return CalibrationResult(
    calibrated_twin=calibrated_twin,
    diagnostics=optimizer.get_diagnostics()
)
    \end{verbatim}
\end{enumerate}

\textbf{Registry Integration:}

Each calibration session is recorded in the universal Git registry with:
\begin{itemize}
    \item Session UUID linking all calibration iterations
    \item Initial twin fingerprint (starting configuration)
    \item Final twin fingerprint (calibrated configuration)
    \item Complete parameter evolution trajectory
    \item Objective function evaluations with timestamps
    \item Authenticated user identity and cryptographic signature
    \item Observation dataset fingerprints used as calibration targets
\end{itemize}

\textbf{Provenance Chain:}

The calibrated twin maintains bidirectional linkage:
\begin{verbatim}
calibrated_twin.provenance = {
    'parent_twin': self.registry_fingerprint,
    'calibration_session': session_uuid,
    'method': 'self_fitting',
    'algorithm': optimization_algorithm,
    'observation_datasets': [obs.fingerprint for obs in targets],
    'user': auth_manager.get_user_id(private_key),
    'timestamp': datetime.now(timezone.utc).isoformat()
}
\end{verbatim}

\textbf{Integration with Estimation Layer:}

The \texttt{self\_fitting()} method delegates computational tasks to the Estimation Layer:

\begin{itemize}
    \item \textbf{Observation management}: \texttt{EstimationLayer.get\_observations()}
    \item \textbf{Simulation execution}: \texttt{EstimationLayer.run\_simulation(parameters)}
    \item \textbf{Gradient computation}: \texttt{EstimationLayer.compute\_gradients()} for adjoint methods
    \item \textbf{Likelihood evaluation}: \texttt{EstimationLayer.evaluate\_likelihood()} for Bayesian inference
    \item \textbf{Ensemble coordination}: \texttt{EstimationLayer.run\_ensemble()} for EnKF or Monte Carlo
    \item \textbf{Bayesian inference integration}: \texttt{EstimationLayer.run\_bayesian\_inference()} for multi-chain MCMC
    \item \textbf{Frequency-domain calibration}: \texttt{EstimationLayer.run\_frequency\_calibration()} for frequency-domain parameter identification
\end{itemize}

\textbf{Multi-Stage Workflow Support:}

For complex calibration scenarios requiring integration across multiple physical processes and observation types, the method supports multi-stage workflows:

\begin{verbatim}
# Multi-stage configuration example
workflow_config = {
    'stages': [
        {
            'name': 'frequency_domain',
            'algorithm': 'hymit',
            'observations': ['discharge', 'recharge'],
            'parameters': ['HRU_efficiency', 'rainfall_response']
        },
        {
            'name': 'temporal_recharge',
            'algorithm': 'dream_surface',
            'observations': ['recharge_time_series'],
            'parameters': ['infiltration_params']
        },
        {
            'name': 'hydrogeological_reference',
            'algorithm': 'hymit_piezometric',
            'observations': ['piezometric_heads'],
            'parameters': ['transmissivity', 'storativity']
        },
        {
            'name': 'bayesian_inversion',
            'algorithm': 'dream',
            'observations': ['all'],
            'parameters': ['conductivity_field', 'storage_field'],
            'adaptive_mesh': True
        }
    ]
}

result = twin.self_fitting(
    workflow_stages=workflow_config,
    private_key=key
)
\end{verbatim}

Each stage produces intermediate calibrated twins that are registered with provenance linkage, enabling full traceability from initial frequency-domain analysis through final Bayesian parameter posteriors.

\textbf{Error Handling:}

The method includes comprehensive error checking:

\begin{itemize}
    \item \textbf{Authentication failures}: Logged and raised as \texttt{AuthenticationError}
    \item \textbf{Non-convergence}: Logged with partial results and raised as \texttt{ConvergenceWarning}
    \item \textbf{Simulation failures}: Logged with parameter values and raised as \texttt{SimulationError}
    \item \textbf{Invalid parameters}: Physical constraints checked before simulation execution
\end{itemize}

\section{Persistence and Bancarisation}

HT inherits from \texttt{HTPersistenceMixin}, which provides:
\begin{itemize}
    \item \texttt{HydrologicalTwin.to\_pickle(path)}
    \item \texttt{HydrologicalTwin.from\_pickle(path)}
\end{itemize}

This enables:
\begin{itemize}
    \item caching of fully built hydrological twins,
    \item fast reloads in new QGIS sessions,
    \item the creation of a future \emph{HydroTwin Hub} of \texttt{.pkl} snapshots.
\end{itemize}

Each snapshot stores:
\begin{itemize}
    \item a schema version,
    \item the class name,
    \item the serialized HT instance.
\end{itemize}

\section{Interface–Backend Contract}

The QGIS plugin must interact only with:
\begin{itemize}
    \item \texttt{HydrologicalTwin}
\end{itemize}

and never directly with:
\begin{itemize}
    \item \texttt{Compartment}
    \item \texttt{Mesh}
    \item \texttt{Observations}
    \item \texttt{Manage.*}
\end{itemize}

This guarantees:
\begin{itemize}
    \item a clear API contract,
    \item easier refactoring,
    \item easier automated testing,
    \item reuse by other tools (CLI, notebooks, web services).
\end{itemize}
