\section{Service Specifications and Delivery Roadmap}

\subsection{Service specification baseline}

Before defining use cases, the White Book must specify the service perimeter exposed by \hydrot. The current target service portfolio is ordered from public exposure to private computation:

\begin{enumerate}
\item \textbf{Public rendering service.}
\begin{itemize}
    \item \textbf{Purpose}: publish maps, plots, dashboards, and aggregated indicators for open consultation.
    \item \textbf{Inputs}: validated hypercubes, rendering parameters, masks, temporal and spatial aggregation operators.
    \item \textbf{Outputs}: non-reversible visualizations, public reports, and aggregated statistics that do not reveal raw hypercube values.
    \item \textbf{Access}: public.
\end{itemize}

\item \textbf{Private data access and computation service.}
\begin{itemize}
    \item \textbf{Purpose}: expose extraction, comparison, transformation, and scenario-building methods to entitled users.
    \item \textbf{Inputs}: validated twin state, user request, tokenized proof of purchase, and cryptographic authentication material.
    \item \textbf{Outputs}: extracted subsets, analysis-ready datasets, derived computational artefacts, and authenticated audit traces.
    \item \textbf{Access}: private, subject to proof of purchase by cryptocurrency and blockchain-anchored entitlement verification.
\end{itemize}

\item \textbf{Private simulation and estimation service.}
\begin{itemize}
    \item \textbf{Purpose}: execute simulations, parameter updates, self-fitting workflows, frequency-domain calibration, and time-domain Bayesian inference.
    \item \textbf{Inputs}: model configuration, private parameterizations, observations, priors, and estimation settings.
    \item \textbf{Outputs}: new twin states, calibrated parameters, posterior distributions, and provenance-rich validation records.
    \item \textbf{Access}: restricted private tier.
\end{itemize}

\item \textbf{Registry and audit service.}
\begin{itemize}
    \item \textbf{Purpose}: register state transitions, access events, entitlement checks, and publication events.
    \item \textbf{Inputs}: git provenance, environment fingerprints, authenticated user claims, and validation events.
    \item \textbf{Outputs}: append-only audit records and reproducibility evidence.
    \item \textbf{Access}: mixed; publication traces can be public while sensitive computational traces remain private.
\end{itemize}
\end{enumerate}

\subsection{Roadmap for White Book professionalization}

The issue addressed by this update can be translated into the following delivery roadmap:

\begin{enumerate}
\item \textbf{Clarify the managed flow.} Make the input-output chain explicit: data sources, models, parameterizations, entitlement proofs, computational layers, public renderings, and private outputs.
\item \textbf{Stabilize the semantics.} Describe \hydrot\ as the authoritative backend contract coordinating reproducibility, access control, and service exposure for \texttt{HydrologicalTwinAlphaSeries} and \cwv.
\item \textbf{Formalize permission levels.} Distinguish public visualization from private computation, and specify that computational methods are unlocked only by blockchain-based proof of purchase through cryptocurrency.
\item \textbf{Define user profiles.} Separate public observers, analysts, operators, subscribers, and auditors so that access rules become operational rather than implicit.
\item \textbf{Specify services before scenarios.} Present rendering, computation, estimation, and registry services first; only then describe the use cases that consume them.
\end{enumerate}

This sequencing is consistent with the present implementation trajectory: \texttt{HydrologicalTwinAlphaSeries} remains the standalone backend package, while \cwv\ remains the visualization client consuming public and private services through controlled interfaces.

\section{Use Case 1: Instantiation and Scientific Integrity Verification - \texttt{private}}

\subsection{Context and Objective}

Instantiating a \hydrot\ instance is the foundational operation that establishes a reproducible, git-synchronized representation of a hydrological system. This use case requires private-key authentication and performs comprehensive integrity verification to ensure that all components---model software, data, parameters, and spatial supports---are properly versioned and internally consistent.

\subsection{Access Level}

\textbf{Private-key authentication and tokenized entitlement required.}

Only authenticated users holding a valid private credential and an active tokenized entitlement can instantiate a private \hydrot\ instance. This ensures that the creation of digital twins is controlled, traceable, and linked to specific actors.

\subsection{Operational Workflow}

The instantiation process follows a strict validation sequence:

\begin{enumerate}
\item \textbf{Metadata consistency check}: The system verifies that all \texttt{GitSynchroRecord} objects are resolvable. This includes:
\begin{itemize}
    \item Model software commit hashes
    \item Data repository states
    \item Parameter repository states
    \item Configuration file versions
\end{itemize}

\item \textbf{Deterministic integrity check}: The system verifies that the declared computational environment can reproduce the expected simulation artefacts and that the resulting hypercube fingerprint matches the registered reference state.

\item \textbf{Private-key authentication}: The system validates the user's private key and logs the authentication event with:
\begin{itemize}
    \item UTC timestamp
    \item User identity
    \item Host metadata
    \item Cryptographic signature
\end{itemize}

\item \textbf{Entitlement verification}: The system checks that the actor holds a valid blockchain-anchored proof of purchase authorizing private instantiation and computation services for the requested privacy tier.

\item \textbf{Git provenance verification}: Each component must have a clean working tree (no dirty state) or explicitly declared modifications. The system computes deterministic version fingerprints for all components.

\item \textbf{Registry append}: If all checks pass, the validated twin instance is appended to the universal Git registry with a hash-chained entry linking it to previous states.
\end{enumerate}

\subsection{Scientific Integrity Certification}

Upon successful instantiation, \hydrot\ certifies that:

\begin{itemize}
\item All simulations can be reproduced from the provided metadata.
\item No silent modifications or drift have occurred.
\item The complete computational context is captured and fingerprinted.
\item The twin instance has a unique, immutable identity in the space-state continuum.
\end{itemize}

If any verification step fails, the instantiation is aborted and the system logs:

\begin{verbatim}
Error: Access denied. Invalid metadata, private-key, or entitlement.
Reason: [specific verification failure]
\end{verbatim}

\subsection{Output and Traceability}

A successfully instantiated \hydrot\ produces:

\begin{itemize}
\item A validated digital twin object with complete \texttt{GitSynchroRecord} provenance
\item An immutable registry entry in the universal ledger
\item A cryptographic fingerprint uniquely identifying this space-state configuration
\item Audit logs linking the instantiation to the authenticated user
\end{itemize}

\section{Use Case 2: Public Visualization and Basic Statistics - \texttt{public}}

\subsection{Context and Objective}

This use case addresses the needs of public users who require access to simulation results for visualization, basic statistical analysis, and spatial exploration without exposing raw data or proprietary parameters. It corresponds to the public rendering capabilities provided through the \cwv\ interface.

\subsection{Access Level}

\textbf{Public access (no authentication required).}

Any user can access simulation results through controlled temporal and spatial aggregation in the \texttt{rendering} layer. This ensures transparency while protecting sensitive information.

\subsection{Available Operations}

Public users can perform the following operations through the \texttt{rendering} layer:

\begin{itemize}
\item \textbf{Spatial visualization}: Display maps of simulated variables (water table elevation, discharge, recharge) with standard symbolization and coordinate reference system enforcement.

\item \textbf{Temporal visualization}: Plot time series of basin-averaged or station-specific variables.

\item \textbf{Basic statistics}: Access pre-computed statistics including:
\begin{itemize}
    \item Mean, median, standard deviation
    \item Temporal aggregates (monthly, seasonal, annual)
    \item Spatial aggregates (basin-wide, aquifer-scale)
\end{itemize}

\item \textbf{Metadata inspection}: View provenance information including:
\begin{itemize}
    \item Model software version (commit hash, branch, tag)
    \item Data sources (without exposing raw values)
    \item Parameter existence (without revealing numerical values)
    \item Simulation execution timestamp
\end{itemize}
\end{itemize}

\subsection{Restricted Access to Raw Data}

Public users \textbf{cannot}:

\begin{itemize}
\item Extract raw NumPy hypercube arrays
\item Access full-resolution spatial grids
\item View or modify model parameters
\item Execute new simulations
\item Apply arbitrary temporal or spatial operators beyond pre-defined aggregations
\end{itemize}

This rule is fundamental: public visualization is permitted only insofar as it does not disclose the raw numerical content of the underlying hypercubes.

\subsection{Implementation through CaWaQS-ViZ}

The public visualization interface provides:

\begin{itemize}
\item QGIS-compatible vector and raster layers
\item Interactive map navigation with controlled zoom levels
\item Export capabilities for maps and plots (PNG, PDF formats)
\item CSV export of aggregated statistics only
\end{itemize}

All rendering operations are reproducible: each visualization includes provenance metadata linking it to the specific \hydrot\ fingerprint and rendering parameters.

\subsection{Transparency without Exposure}

This use case demonstrates how \hydrot\ reconciles scientific openness with operational constraints. Public users can:

\begin{itemize}
\item Verify that simulations exist and are properly versioned
\item Explore results at meaningful aggregation scales
\item Reproduce visualizations from documented rendering scripts
\end{itemize}

However, they cannot access proprietary parameters or raw data, ensuring confidentiality where required.

\section{Use Case 3: SubTwin Extraction and Nested Instantiation - \texttt{private}}

\subsection{Context and Objective}

A common operational requirement is to extract a spatially or temporally refined digital twin from a parent \hydrot\ instance. This creates a nested hierarchy of twins, each inheriting provenance from its parent while potentially introducing localized refinements.

Typical applications include:

\begin{itemize}
\item Extracting a territory-scale twin from a regional-scale parent
\item Creating a wellfield-focused twin from a territory-scale parent
\item Generating a time-window-specific twin for detailed analysis of a specific hydrological  event
\end{itemize}

\subsection{Access Level}

\textbf{Private-key authentication and tokenized entitlement required.}

SubTwin extraction involves accessing raw simulation outputs and potentially modifying spatial or temporal supports, which are restricted operations.

\subsection{Operational Workflow}

The extraction process follows these steps:

\begin{enumerate}
\item \textbf{Parent twin validation}: Verify that the parent \hydrot\ instance is properly instantiated and registered.

\item \textbf{Extraction specification}: Define the spatial extent, temporal window, and variable subset for the SubTwin:
\begin{itemize}
    \item Spatial filter: bounding box, catchment polygon, or mesh subset
    \item Temporal filter: date range, specific event windows
    \item Variable selection: subset of state variables to retain
\end{itemize}

\item \textbf{Data extraction}: Apply extraction operators from the Analysis Layer to create SubTwin hypercubes.

\item \textbf{Metadata inheritance}: The SubTwin inherits \texttt{GitSynchroRecord} provenance from the parent, with additional metadata recording:
\begin{itemize}
    \item Parent twin fingerprint
    \item Extraction operators applied
    \item Spatial and temporal bounds
    \item Authenticated user performing the extraction
\end{itemize}

\item \textbf{SubTwin instantiation}: The extracted SubTwin is instantiated as a new, independently versioned \hydrot\ object.

\item \textbf{Registry linkage}: The SubTwin is registered with explicit linkage to its parent in the universal registry.
\end{enumerate}

\subsection{Nested Functionality and Hierarchy}

SubTwins maintain a pointer to their parent twin, creating a hierarchical structure. This can be implemented in two ways:

\begin{itemize}
\item \textbf{Option 1 (via global registry)}: SubTwins reference their parent through registry fingerprints, enabling distributed and independent versioning.

\item \textbf{Option 2 (nested containment)}: SubTwins are contained as child objects within their parent class, ensuring tighter coupling and automatic propagation of parent updates.
\end{itemize}

The preferred implementation is \textbf{Option 2 (nested containment)}, which simplifies parent-child synchronization and ensures that SubTwins remain consistent with their parent's evolution.

\subsection{Concrete Example: Wellfield Extraction}

Consider a regional groundwater model covering 10,000 km² with a spatial resolution of 1 km. An operational user needs to analyze a specific wellfield covering 50 km² with higher temporal resolution.

The workflow proceeds as follows:

\begin{enumerate}
\item Authenticate with private key and load the regional parent twin.
\item Define a spatial polygon around the wellfield area.
\item Extract relevant variables (hydraulic head, pumping rates, recharge).
\item Instantiate the wellfield SubTwin with inherited provenance.
\item Register the SubTwin with explicit linkage to the parent.
\item Perform wellfield-specific analyses using the Analysis Layer.
\end{enumerate}

The resulting SubTwin is fully traceable: its provenance explicitly documents that it is a spatial subset of a specific parent twin, extracted by a specific user at a specific time.

\section{Use Case 4: Advanced Analysis and Uncertainty Quantification _ \texttt{private}}

\subsection{Context and Objective}

This use case addresses advanced analytical workflows that require full access to raw simulation outputs and the ability to execute new model runs. It supports:

\begin{itemize}
\item Parameter calibration and \texttt{self\_fitting()}
\item Uncertainty propagation and sensitivity analysis
\item Bayesian inference and posterior sampling
\item Hybrid physics-AI model development
\end{itemize}

\subsection{Access Level}

\textbf{Private-key authentication and tokenized entitlement required.}

These operations involve modifying parameters, executing new simulations, and accessing raw hypercube data.

\subsection{Parameter Calibration Workflow}

The parameter calibration use case follows this sequence:

\begin{enumerate}
\item \textbf{Load parent twin}: Authenticate and instantiate a baseline \hydrot\ with initial parameter estimates.

\item \textbf{Define calibration objectives}: Specify target observations, likelihood functions, and prior distributions.

\item \textbf{Execute calibration algorithm}: Use the Estimation Layer to run:
\begin{itemize}
    \item Gradient-based optimization (adjoint methods)
    \item Markov Chain Monte Carlo (MCMC) sampling
    \item Ensemble Kalman Filtering (EnKF)
    \item Deep learning surrogate models for parameter emulation
\end{itemize}

\item \textbf{Generate ensemble of hypercubes}: Each calibration iteration produces a new hypercube instance with updated parameters and corresponding simulation outputs.

\item \textbf{Registry and provenance}: Each hypercube is registered with its corresponding meta-data gitSynchronizable :
\begin{itemize}
    \item Parent twin fingerprint
    \item Calibration algorithm and hyperparameters
    \item Likelihood evaluation and posterior statistics
    \item Authenticated user and timestamp
\end{itemize}
\end{enumerate}

\subsection{The \texttt{.self\_fitting()} Method}

The \texttt{.self\_fitting()} method provides an integrated, automated calibration workflow within the \hydrot\ framework. This method encapsulates the complete calibration procedure as a native operation accessible only after successful instantiation with private-key authentication and entitlement verification.

\subsubsection{Access Requirements and Preconditions}

The \texttt{.self\_fitting()} method requires:

\begin{enumerate}
\item \textbf{Successful twin instantiation}: The method is only accessible after the \hydrot\ instance has been instantiated with full scientific integrity verification.

\item \textbf{Private-key authentication and entitlement verification}: As a parameter-modifying operation, \texttt{.self\_fitting()} requires authenticated access with a valid private key and an active blockchain-anchored proof of purchase.

\item \textbf{Certified reproducibility}: The initial simulation state must be certified as reproducible, ensuring that all subsequent calibration iterations maintain traceability.

\item \textbf{Observation data availability}: Target observations must be properly registered in the data layer with complete \texttt{GitSynchroRecord} provenance.
\end{enumerate}

\subsubsection{Method Signature and Parameters}

The method signature follows the general pattern:

\begin{verbatim}
twin.self_fitting(
    target_observations: List[ObservationSet],
    parameters_to_calibrate: List[ParameterDescriptor],
    optimization_algorithm: str,
    convergence_criteria: Dict[str, float],
    private_key: str,
    **algorithm_specific_kwargs
) -> CalibrationResult
\end{verbatim}

Key parameters include:

\begin{itemize}
\item \textbf{target\_observations}: A list of observation sets (piezometric heads, discharge measurements, recharge estimates) used as calibration targets. Each observation set must include spatial locations, temporal coverage, and uncertainty estimates.

\item \textbf{parameters\_to\_calibrate}: A structured description of which model parameters should be adjusted, including:
\begin{itemize}
    \item Parameter identifiers and spatial supports
    \item Prior distributions or feasible ranges
    \item Sensitivity indicators or hierarchical groupings
\end{itemize}

\item \textbf{optimization\_algorithm}: Selection of the calibration algorithm:
\begin{itemize}
    \item \texttt{'gradient\_descent'}: Adjoint-based gradient optimization
    \item \texttt{'mcmc'}: Markov Chain Monte Carlo sampling
    \item \texttt{'temporal\_bayesian\_inference'}: Time-domain Bayesian inference
    \item \texttt{'enkf'}: Ensemble Kalman Filter
    \item \texttt{'pso'}: Particle Swarm Optimization
    \item \texttt{'multi\_stage\_bayesian'}: Multi-stage workflow combining frequency and temporal domain calibration with Bayesian inference
    \item \texttt{'custom'}: User-defined calibration procedure
\end{itemize}

\item \textbf{convergence\_criteria}: Dictionary specifying when to terminate optimization:
\begin{itemize}
    \item \texttt{max\_iterations}: Maximum number of simulation runs
    \item \texttt{tolerance}: Minimum improvement threshold
    \item \texttt{objective\_function\_value}: Target goodness-of-fit
\end{itemize}

\item \textbf{private\_key}: Cryptographic key authenticating the user and authorizing parameter modification operations.
\end{itemize}

\subsubsection{Self-Fitting Workflow}

The \texttt{.self\_fitting()} method executes the following automated procedure:

\begin{enumerate}
\item \textbf{Authentication and authorization}:
\begin{itemize}
    \item Validate the provided private key
    \item Log the calibration initiation event with user identity and timestamp
    \item Verify that the twin is in a valid state for calibration
\end{itemize}

\item \textbf{Objective function definition}:
\begin{itemize}
    \item Extract target observation values and spatial-temporal locations
    \item Define the mismatch metric (RMSE, Nash-Sutcliffe efficiency, log-likelihood)
    \item Weight different observation types according to their uncertainties
    \item Establish regularization terms to prevent overfitting
\end{itemize}

\item \textbf{Parameter space exploration}:
\begin{itemize}
    \item Initialize parameter values from prior distributions or user-specified starting points
    \item For each iteration:
    \begin{itemize}
        \item Propose new parameter values according to the optimization algorithm
        \item Update the model configuration in a controlled manner
        \item Execute a new simulation run
        \item Extract simulation outputs at observation locations
        \item Evaluate the objective function
        \item Update parameter estimates based on algorithm-specific rules
    \end{itemize}
    \item Monitor convergence and detect stagnation or divergence
\end{itemize}

\item \textbf{Provenance tracking}:
\begin{itemize}
    \item Each simulation iteration generates a new \texttt{GitSynchroRecord}
    \item Parameter values at each iteration are logged with complete provenance
    \item Objective function evaluations are recorded in the universal registry
    \item All intermediate twins are registered as a calibration ensemble
\end{itemize}

\item \textbf{Convergence detection and termination}:
\begin{itemize}
    \item Apply convergence criteria to determine when calibration is complete
    \item Identify the optimal parameter set or posterior distribution
    \item Generate diagnostic plots (parameter evolution, objective function trajectory)
    \item Validate that the calibrated twin satisfies physical constraints
\end{itemize}

\item \textbf{Result instantiation}:
\begin{itemize}
    \item Instantiate a new \hydrot\ with the calibrated parameters
    \item Link this calibrated twin to the initial twin via registry references
    \item Compute posterior uncertainty estimates if using Bayesian methods
    \item Generate validation metrics comparing calibrated simulation to observations
\end{itemize}
\end{enumerate}

\subsubsection{Registry Integration and Audit Trail}

The \texttt{.self\_fitting()} method maintains complete traceability through the universal Git registry:

\begin{itemize}
\item \textbf{Calibration session record}: A unique identifier for the entire \texttt{.self\_fitting()} operation, including:
\begin{itemize}
    \item Initial twin fingerprint (starting configuration)
    \item Final twin fingerprint (calibrated configuration)
    \item Authenticated user performing the calibration
    \item Calibration algorithm and hyperparameters
    \item Convergence diagnostics and final objective function value
\end{itemize}

\item \textbf{Iteration-level tracking}: Each simulation iteration during calibration is registered with:
\begin{itemize}
    \item Parameter values tested
    \item Objective function evaluation
    \item Simulation execution timestamp
    \item Numerical convergence status
\end{itemize}

\item \textbf{Observation linkage}: The registry explicitly links the calibrated twin to the observation datasets used as targets, ensuring that:
\begin{itemize}
    \item Calibration is reproducible if observation data evolves
    \item Data provenance is maintained for scientific audit
    \item Observation updates can trigger recalibration workflows
\end{itemize}
\end{itemize}

\subsubsection{Output and Return Values}

The \texttt{.self\_fitting()} method returns a \texttt{CalibrationResult} object containing:

\begin{itemize}
\item \textbf{calibrated\_twin}: A new \hydrot\ instance with optimized parameters
\item \textbf{parameter\_evolution}: Time series of parameter values across iterations
\item \textbf{objective\_function\_history}: Trajectory of the objective function during optimization
\item \textbf{convergence\_diagnostics}: Statistical tests and plots validating convergence
\item \textbf{validation\_metrics}: Goodness-of-fit statistics comparing calibrated simulation to observations
\item \textbf{posterior\_distribution}: (if Bayesian) Samples from the posterior parameter distribution
\item \textbf{registry\_fingerprint}: Unique identifier for this calibration session in the universal registry
\end{itemize}

\subsubsection{Integration with Estimation Layer}

The \texttt{.self\_fitting()} method is implemented as a high-level interface to the Estimation Layer, which provides:

\begin{itemize}
\item \textbf{Observation extraction}: Methods to retrieve observation values at simulation grid locations
\item \textbf{Simulation execution}: Controlled interfaces for running the physical model with updated parameters
\item \textbf{Gradient computation}: Adjoint or finite-difference gradients for gradient-based optimization
\item \textbf{Likelihood evaluation}: Probabilistic scoring functions for Bayesian inference
\item \textbf{Ensemble management}: Parallel execution of multiple simulation runs for ensemble methods
\end{itemize}

\subsubsection{Multi-Stage Calibration Workflow with Adaptive Meshing}

For complex hydrological systems requiring integration of multiple observation types and physical process representations, the \texttt{.self\_fitting()} method supports a multi-stage workflow that combines frequency-domain and temporal-domain calibration with adaptive meshing techniques. This advanced workflow is particularly suited for integrated surface-groundwater models.

\paragraph{Stage 1: Frequency Domain Calibration}

The first stage establishes optimal hydrological process parameters through frequency-domain analysis:

\begin{itemize}
\item \textbf{Conceptual option}: Calibrate using Hydrological Response Units (HRU), rainfall fields, evapotranspiration fields, HRU maps, and discharge time series linked to watersheds

\item \textbf{Energy-based option}: Utilize effective rainfall from a time-domain forward model (physics-based) validated over long-term periods (typically 17+ years), to minimize the mismatch between effective rainfall and observed discharge

\item \textbf{Frequency-domain calibration}: Apply this method to transform effective rainfall into discharge, determining 5 optimal parameters per sub-watershed. This establishes the hydrological observational reference framework. The implementation is natively integrated within \hydrot
\end{itemize}

\paragraph{Stage 2: Temporal Domain Recharge Parameter Optimization}

The second stage refines recharge model parameters in the temporal domain:

\begin{itemize}
\item \textbf{Conceptual option}: Optimize parameters at the HRU scale

\item \textbf{Energy-based option}: Optimize the time-domain forward model to reproduce the frequency-domain-derived recharge results at the sub-watershed scale

\item \textbf{Bayesian Surface Calibration}: Optional application of time-domain Bayesian inference for surface process calibration
\end{itemize}

\paragraph{Stage 3: Hydrogeological Observational Reference Framework}

The third stage establishes hydrogeological parameters through frequency-domain analysis of subsurface observations:

\begin{itemize}
\item \textbf{Frequency-domain hydrological mode}: Derive mean hydraulic diffusivity ($D$) and equivalent conductivity ($K$) per hydrological observation basin from discharge data

\item \textbf{Frequency-domain piezometric mode}: Estimate transmissivity ($T$) and storativity ($S$) at piezometer locations from groundwater head time series

\item \textbf{Cross-validation}: The frequency-domain piezometric estimates are validated against pumping test results. Observed systematic biases (frequency-domain $K$ values typically exceed geometric mean $K$ from pumping tests) are quantified

\item \textbf{Offset computation}: Calculate the offset between geometric-mean frequency-domain piezometric parameters and frequency-domain hydrological diffusivity on initial parameter fields. This offset is subsequently minimized in temporal domain during Stage 4, maximizing exploitation of all available observations
\end{itemize}

\paragraph{Stage 4: Bayesian Inversion with Multi-Chain Markov Methods}

The final stage performs comprehensive Bayesian parameter estimation in the temporal domain:

\begin{itemize}
\item \textbf{Time-domain Bayesian inference}: Apply time-domain Bayesian inference methods for multi-chain Markov Chain Monte Carlo (MCMC) sampling. This approach provides comprehensive uncertainty quantification through posterior distributions

\item \textbf{Adaptive meshing}: Leverage the hydrogeological observational reference framework (from Stage 3 piezometric analysis) in conjunction with the hydrological reference (from Stage 1 discharge analysis) to define an observationally-constrained adaptive mesh

\item \textbf{Parameter targets}: Optimize hydrogeological parameters ($K/T$ and $S$) across the adaptive mesh

\item \textbf{Uncertainty quantification}: The Bayesian inference approach provides both optimal parameter estimates and full posterior distributions, comprehensively characterizing parameter uncertainties
\end{itemize}

\paragraph{Workflow Integration in HydroTwin}

This multi-stage procedure is orchestrated through a specialized configuration of the \texttt{.self\_fitting()} method:

\begin{verbatim}
result = twin.self_fitting(
    target_observations={
        'discharge': discharge_time_series,
        'piezometry': head_time_series,
        'pumping_tests': test_results
    },
    parameters_to_calibrate={
        'stage_1': ['HRU_parameters', 'rainfall_efficiency'],
        'stage_2': ['recharge_model_params'],
        'stage_3': ['hydraulic_diffusivity', 'transmissivity'],
        'stage_4': ['conductivity_field', 'storativity_field']
    },
    optimization_algorithm='multi_stage_bayesian',
    workflow_stages=[
        {'name': 'frequency_domain_calibration', 'domain': 'frequency'},
        {'name': 'temporal_recharge', 'domain': 'temporal'},
        {'name': 'hydrogeological_reference', 'domain': 'frequency'},
        {'name': 'temporal_bayesian_inference', 'domain': 'temporal'}
    ],
    adaptive_meshing=True,
    convergence_criteria={
        'max_iterations_per_stage': [100, 50, 100, 1000],
        'tolerance': 1e-4
    },
    private_key=user_key
)
\end{verbatim}

Each stage produces intermediate \hydrot\ instances that are registered in the universal Git registry, maintaining complete provenance from initial frequency-domain analysis through final Bayesian parameter distributions.

\subsubsection{Example: Automatic Calibration of Hydraulic Conductivity}

Consider a typical groundwater model calibration scenario:

\begin{enumerate}
\item \textbf{Instantiate baseline twin}:
\begin{verbatim}
twin = HydrologicalTwin(
    config=baseline_config,
    private_key=user_key
)
\end{verbatim}

\item \textbf{Define calibration targets}:
\begin{verbatim}
observations = [
    ObservationSet(
        variable='hydraulic_head',
        locations=piezometer_network,
        values=measured_heads,
        uncertainty=measurement_error
    )
]
\end{verbatim}

\item \textbf{Execute \texttt{self\_fitting()}}:
\begin{verbatim}
result = twin.self_fitting(
    target_observations=observations,
    parameters_to_calibrate=[
        ParameterDescriptor(
            name='hydraulic_conductivity',
            spatial_support='aquifer_layer_1',
            prior='log_normal(mean=-5, std=1)'
        )
    ],
    optimization_algorithm='gradient_descent',
    convergence_criteria={
        'max_iterations': 50,
        'tolerance': 1e-4
    },
    private_key=user_key
)
\end{verbatim}

\item \textbf{Validate calibrated twin}:
\begin{verbatim}
calibrated_twin = result.calibrated_twin
print(f"Final RMSE: {result.validation_metrics['rmse']}")
print(f"Nash-Sutcliffe: {result.validation_metrics['nse']}")
\end{verbatim}
\end{enumerate}

This workflow demonstrates how \texttt{.self\_fitting()} encapsulates complex calibration logic into a single, reproducible method call, while maintaining full provenance tracking through the \hydrot\ architecture.

\subsection{Uncertainty Quantification}

For uncertainty analysis, \hydrot\ supports:

\begin{itemize}
\item \textbf{Monte Carlo ensembles}: Generate multiple twins with parameter values sampled from posterior distributions.

\item \textbf{Sensitivity analysis}: Systematically vary parameters and track output variability using:
\begin{itemize}
    \item Sobol indices
    \item Morris screening
    \item Variance-based decomposition
\end{itemize}

\item \textbf{Bayesian model averaging}: Combine predictions from multiple structurally different models (multi-model by design) weighted by their posterior probabilities.
\end{itemize}

Each uncertainty quantification workflow produces a collection of related \hydrot\ instances, all registered and traceable through the universal registry.

\subsection{AI-Enhanced Analysis}

\hydrot\ naturally integrates artificial intelligence methods within its space-state framework:

\begin{itemize}
\item \textbf{Surrogate models}: Train neural networks or Gaussian processes to emulate expensive physical models. The trained models are versioned as \texttt{Software} objects with full provenance.

\item \textbf{Hybrid physics-AI models}: Combine physically based components with data-driven correction terms. Both components are independently versioned and registered.

\item \textbf{Deep learning for parameter estimation}: Use variational autoencoders or generative adversarial networks to explore high-dimensional parameter spaces. Training data and network architectures are registered as space-state objects.
\end{itemize}

All AI workflows maintain full traceability: the training data provenance, model architecture, hyperparameters, and learned weights are captured in \texttt{GitSynchroRecord} objects.

\subsection{Output and Validation}

Advanced analysis workflows produce:

\begin{itemize}
\item Collections of validated \hydrot\ instances representing posterior distributions or ensemble predictions
\item Diagnostic plots and statistical summaries registered as rendering artifacts
\item Provenance chains linking calibrated twins to their parent configurations and observational constraints
\item Immutable registry entries for each analysis step, ensuring reproducibility and audit compliance
\end{itemize}

\section{Summary: Access Control and Use Case Mapping}

The use cases presented in this chapter illustrate the dual-layer architecture of \hydrot:

\begin{itemize}
\item \textbf{Public layer}: Enables transparent exploration of simulation results through rendering and aggregated statistics, supporting scientific openness without compromising sensitive information.

\item \textbf{Private layer}: Requires authentication for operations that access raw data, modify parameters, or execute new simulations, ensuring accountability and traceability for all critical actions.
\end{itemize}

This design reconciles the need for scientific transparency with operational and economic constraints, providing a rigorous foundation for digital hydrology that is both open and secure.

Each use case demonstrates how \hydrot\ operationalizes the architectural principles defined in Chapter 2, ensuring that all workflows---from simple visualization to complex uncertainty quantification---are reproducible, traceable, and audit-ready.
